# ФАЗА 2 — СТАРТОВАЯ СТРАНИЦА БЕЗ ПДн

> Сначала вставь общий контекст из `prompts/00-context.md`, затем — задание ниже.
> Предусловие: Фаза 1 завершена (таблица `candidates`, `pin_lookup`, `SERVER_PEPPER`).

## Задание

### 2.1 Экран ввода (app/candidate/skillproof/page.tsx, стадия 'disclaimer')
- УДАЛИ поля «Имя и фамилия» и «Email» и всё связанное состояние (`candidateName`,
  `candidateEmail`), а также отправку письма (`sendResultEmail`) и её статусы.
- Добавь поле ввода PIN: ровно 4 цифры (используй имеющийся `input-otp` или обычный input с
  `inputMode="numeric"`, `pattern="[0-9]*"`, `maxLength=4`). Никаких других данных.
- Текст-подсказка: «Придумайте 4-значный код. Он заменяет логин и понадобится, чтобы позже
  скачать сертификат. Запомните его — восстановить код невозможно.»
- Запрети слабые PIN: 0000, 1111 … 9999, 1234, 4321, 0123 и другие тривиальные
  последовательности (короткий blacklist). Покажи понятную ошибку.
- Кнопка «Начать тестирование» активна только при валидном PIN.
- Согласие ПДн: персональных данных больше нет. Замени чекбокс «согласие на обработку ПДн» на
  краткое согласие с правилами тестирования и прокторинга + ссылку на `/privacy`. Обнови текст
  `/privacy`: явно укажи, что персональные данные не собираются, идентификация анонимная по PIN,
  фиксируются только события прокторинга и результаты теста.

### 2.2 Регистрация PIN (серверный экшен, 'use server')
- Экшен `registerPin(pin)`: валидирует формат и blacklist → считает `pin_lookup` → пытается
  INSERT в `candidates`. Полагайся на UNIQUE-нарушение как на сигнал «PIN занят»
  (`INSERT ... ON CONFLICT DO NOTHING` / перехват ошибки уникальности) — НЕ делай
  «SELECT потом INSERT», это гонка.
- Если PIN занят: верни понятное сообщение «Этот код уже занят, придумайте другой» и предложи
  2–3 свободных варианта (сгенерируй случайные и проверь их одним запросом).
- ВАЖНО: сообщение «код занят» раскрывает существование PIN. Поэтому обязателен rate-limit
  (Фаза 5) и одинаковое время ответа. Не показывай, сколько всего пользователей.

### 2.3 Гейт повторных попыток
- Замени `getCompletionByEmail` на `getCompletionByPin(pin)`: ищет по `pin_lookup`, возвращает
  число попыток и лучший результат. Логика `MAX_ATTEMPTS` сохраняется. При ошибке БД — fail-open,
  как сейчас.
- Стадия 'already-completed' показывает результат без ПДн (PIN, направление, балл, дата,
  ID сертификата).

## Критерий готовности фазы
- На стартовой странице только ввод PIN, нет имени/email, нет отправки писем.
- Слабые PIN отклоняются; регистрация устойчива к гонкам.
- Гейт попыток работает по PIN.
- Отчёт: изменённые файлы.
