# ФАЗА 3 — ВОССТАНОВЛЕНИЕ СЕРТИФИКАТА ПО PIN

> Сначала вставь общий контекст из `prompts/00-context.md`, затем — задание ниже.
> Предусловие: Фазы 1–2 завершены.

## Задание

### 3.1 Блок «Уже проходили тест? Скачать сертификат» на стартовой странице
- Поле ввода 4-значного PIN + кнопка «Найти сертификат».
- Серверный экшен `getCertificatesByPin(pin)`: по `pin_lookup` находит все ПРОЙДЕННЫЕ
  (`passed=true`) результаты кандидата и возвращает только несекретные поля: `certificateId`,
  `specialization`, `score`, `isClean`, `issuedAt`. Никаких ПДн, никакого детального лога
  прокторинга.
- Если найдено: покажи карточку(и) сертификата с кнопками «Скачать PDF» (используй существующий
  `lib/certificate-pdf.ts`) и «Проверить» (ссылка на `/verify/{certificateId}`).
- Если не найдено или тест не пройден: нейтральное сообщение «Сертификат по этому коду не
  найден». Формулировка ОДИНАКОВАЯ для «PIN не существует» и «PIN есть, но тест не пройден» —
  чтобы не подтверждать существование кода.
- Блок ОБЯЗАН быть под rate-limit и блокировкой при переборе (Фаза 5).

### 3.2 Сертификат и /verify
- Убери имя кандидата из карточки сертификата (`components/certificate/certificate-card.tsx`),
  из PDF (`lib/certificate-pdf.ts`) и со страницы `/verify`. Вместо имени показывай PIN или
  обезличенный идентификатор (например «Кандидат #1234»).
- `getCertificateById` больше не возвращает `candidateName`. Проверь, что `/verify` не отдаёт
  ничего персонального.

## Критерий готовности фазы
- Восстановление по PIN возвращает пройденные сертификаты; неизвестный/непройденный PIN даёт
  единое нейтральное «не найдено».
- Ни в карточке, ни в PDF, ни на /verify нет имени/email.
- Отчёт: изменённые файлы.
